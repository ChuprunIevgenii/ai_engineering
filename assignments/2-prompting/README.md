# Домашнє завдання: Data extraction PDF → JSON

## Базовий код у `starter.py` — реалізуй `extract_text()`, напиши `PROMPT`, опційно `validate_rows()`

## Формат здачі

Заповни `results.md` і додай до Pull Request змінений `starter.py`, `results.md` та згенеровану папку `output/`. Не додавай API-ключі, `.env` або інші секрети.

Вивід `eval.py` у `results.md` має відповідати саме тому `output/`, який ти комітиш: після останнього прогону `starter.py` запусти `uv run eval.py` ще раз і встав цей вивід. Якщо потім перезапускав `starter.py` — оновлюй і `output/`, і вивід eval.

## Мета завдання

Навчитися витягувати структуровані дані з PDF: один скрипт `PDF → текст → LLM → JSON`, який працює, коли верстка і формат файлів різняться.

У вас **5 PDF** з ростером футбольних гравців (5 ліг, 7 команд). Кожен файл зібраний по-іншому — відкрийте їх і подивіться, перш ніж писати промпт.

---

## Що потрібно зробити

1. **`extract_text(pdf_path)`** — витягнути текст з PDF. Бібліотеку обери сам (погугли / PyPI).
   > ⚠️ **Додай бібліотеку в inline-залежності** на початку `starter.py` (блок `# dependencies = [...]`). `uv run` ставить тільки те, що там перелічено, — `pip install` у свій venv не допоможе, і скрипт впаде з `ModuleNotFoundError`. У минулій когорті це була найчастіша помилка.
2. **`PROMPT`** — промпт для LLM, щоб повертав JSON з плоским списком гравців.
3. **(Бонус)** **`validate_rows()`** — відфільтрувати після LLM рядки, які не є реальними гравцями.

Результати — у `output/<stem>.json`. Перевірка: `uv run eval.py`.

## 🛠 Інструментарій

* **LLM:** `openrouter/google/gemini-3.5-flash-lite` (за замовчуванням у `starter.py`). Повний прогін 5 PDF — близько хвилини-двох і ~$0.10.
* **Час і вартість:** `starter.py` друкує час, вартість, кількість токенів і `finish_reason` для кожного PDF, а в кінці — таблицю з TOTAL (зберігається в `output/run_stats.json`; встав її в `results.md`).
* **Reasoning-моделі:** якщо захочеш спробувати reasoning-модель (наприклад, `gemini-3.8-flash`), постав `REASONING_EFFORT = "low"`. Токени на «думання» рахуються в `MAX_TOKENS`: на дефолтному effort вона витрачає ~10k токенів на один PDF і обрізає JSON. Якщо бачиш `УВАГА: відповідь обрізана` — JSON неповний.
* **API ключ:** `export OPENROUTER_API_KEY="sk-or-..."`

```bash
# Усі 5 PDF
uv run starter.py

# Один файл (зручно для ітерацій)
uv run starter.py pdfs/05_album_sheet.pdf

# Оцінка
uv run eval.py
uv run eval.py 05_album_sheet
uv run eval.py --bonus    # бонус: перевірки на 03_watermark
```

## Очікуваний JSON формат

Плоский список гравців у `output/*.json`:

```json
[
  {
    "league": "Premier League",
    "team": "Arsenal",
    "name": "Bukayo Saka",
    "position": "RW",
    "number": 7,
    "age": 23,
    "nationality": "England",
    "phone": "+44 7123 123456",
    "address": "12 King St, London"
  }
]
```

| Поле | Тип | Опис |
|------|-----|------|
| `league` | string | Назва ліги |
| `team` | string | Назва команди |
| `name` | string | Повне ім'я гравця |
| `position` | string \| null | GK, CB, CAM, RW, … |
| `number` | integer \| null | Номер |
| `age` | integer \| null | Вік |
| `nationality` | string \| null | Національність |
| `phone` | string \| null | Телефон |
| `address` | string \| null | Адреса |

## Оцінювання

`eval.py` рахує по кожному PDF окремо:

- **Скільки гравців знайшов** (40%)
- **Точність полів** (60%)

**Зважена оцінка:** `01×1 + 02×2 + 03×3 + 04×2 + 05×2` (знаменник 10)

| Оцінка | Результат |
|--------|-----------|
| ≥ 95%  | Відмінно |
| ≥ 80%  | Добре |
| ≥ 60%  | Прийнятно |
| < 60%  | Потребує доопрацювання |

Бали впиши в [`results.md`](results.md) — **копіпастом** повний вивід `uv run eval.py` (і `--bonus`, якщо робив), запущеного на закоміченому `output/`.

## Бонус A: Фільтрація після екстракції

Допиши `validate_rows()` у `starter.py` — шар перевірок після LLM, який не довіряє ні моделі, ні вмісту PDF.

Подивись очима на свій `output/03_watermark.json` і на сам PDF: знайди рядки, яких там бути не повинно, і зрозумій, звідки вони взялись. Розкажи про це в `results.md`.

Видаляй рядок, тільки якщо це не гравець. Якщо гравець справжній, а одне поле зіпсоване — постав у цьому полі `null` і залиш рядок. Видалений гравець б'є по recall (40% оцінки), а `null` — лише по одному полю.

Перевірка: `uv run eval.py --bonus` (тільки для `03_watermark`, на основну оцінку не впливає).
